# Arm Dashboard serial protocol (v1)

Link: USB serial, 115200 baud, Arduino Mega 2560. Opening the port resets the Mega (~2 s boot).
Host → Mega: ASCII lines ending in `\n`. Tokens separated by spaces. Unknown lines → `{"t":"err","s":"..."}`.
Mega → Host: one JSON object per line (`\n`). Never print anything that isn't a JSON line.

## Hardware (verified against jlc5_backup.kicad_pcb)
- Motor "j2" = driver A2: STEP D27, DIR D29.  Motor "j3" = driver A3: STEP D31, DIR D33.
- EN for all drivers: D43 (LOW = on).  A4988, 1/8 microstep → 1600 steps per motor rev (200 × 8).
- j2 and j3 are the two NEMA 17s of the arm's **differential**: both motors same way = PITCH,
  opposite ways = ROLL. Mixing (in motor steps):  j2 = pitch + roll,  j3 = pitch − roll.
  So pitch_steps = (j2 + j3)/2, roll_steps = (j2 − j3)/2.
  Joint angle (deg) = steps / (1600 × gear / 360), `gear` = motor turns per output turn (default 1, settable).
- Claw: 28BYJ-48 on ULN2003 via J27, AccelStepper HALF4WIRE pins (11, 9, 10, 8) [reversed order, as in the
  current sketch], 4096 half-steps per output rev. 0 = fully open, counts up closing. Optional claw switch
  D32 (to GND) and AS5600 encoder (I2C 0x36, SDA D20 / SCL D21) — keep the existing auto-detect logic.
- Limit switch headers (to GND, INPUT_PULLUP): D22, D24, D26, D28, D30. Wired COM+NC, so normally LOW,
  pressed (or broken wire) = HIGH. A pin that reads HIGH at boot is treated as "not fitted" and ignored.

## No encoders on j2/j3 — how position stays right (open-loop rules the firmware must follow)
1. Position = step count. Every step is generated by AccelStepper with acceleration ramps; never jump speed.
2. Both differential motors are driven as ONE coordinated move: their speeds and accelerations are scaled
   by the same factor so they start, ramp and stop together (otherwise pitch/roll drift during ramps).
3. Conservative defaults that stay below the stall point: max 1200 steps/s, accel 1500 steps/s²
   (both settable; persisted). Speed % scales max speed.
4. Soft limits in joint space (pitch/roll degrees, min/max each). Disabled until set. Motion that would
   cross a limit is ramped to a stop at the limit (start decelerating early enough).
5. Watchdog: if no `V` or `P` line for 400 ms while jogging, decelerate everything to a stop.
6. `trusted` flag: true after `Z` (user marks zero) or after a position restored from EEPROM that was saved
   with drivers on. Becomes false when drivers are disabled (motors limp, can be turned by hand),
   on a stall report, or when restored from EEPROM after the drivers had been turned off. `G` (go to)
   is refused while `trusted` is false.
7. Persistence: when all motion has been stopped for 1 s and the position changed, save j2/j3/claw steps +
   trusted flag to EEPROM (use EEPROM.put; it only writes changed bytes). Also save config (gear, speed,
   accel, limits, claw close limit). EEPROM layout has a magic + version word; bad magic → defaults.
   On boot, restore the saved positions (the arm doesn't move while powered off, but only trust them if
   they were saved with drivers on and nothing moved after).

## Commands (host → Mega)
| Line | Meaning |
|---|---|
| `V <pitch> <roll> <claw>` | Jog velocities, each integer −100..100 (% of current max speed). Sent every 50 ms while keys are held; `V 0 0 0` ramps to a stop. Pitch/roll mixed in firmware; if \|pitch\|+\|roll\| > 100, scale both down so neither motor exceeds max. claw +=close, −=open, respects 0..closeLimit. Also feeds the watchdog. |
| `M <j2> <j3>` | Raw per-motor jog velocity −100..100 (for testing one motor). Same watchdog. |
| `P` | Ping (feeds watchdog, no motion change). |
| `S` | Stop everything now (ramped quick stop for j2/j3 using 3× accel; claw immediate). |
| `G <pitch_deg> <roll_deg>` | Coordinated move to joint position (both motors arrive together). Refused if not trusted or outside limits. |
| `GC <claw_deg>` | Claw to angle (0 = open). |
| `Z` | Current pitch/roll = 0, trusted = true. |
| `ZC` | Claw: current position = 0 (fully open). |
| `HC` | Home claw (existing open-stop / switch / encoder homing logic). |
| `KC` | Claw close limit = current position. |
| `E <0\|1>` | Drivers off/on (D43). Off → trusted = false. |
| `SPD <10..100>` | Speed %. |
| `CFG <gear> <maxSteps> <accel>` | Set gear ratio (float), max steps/s, accel steps/s². Persisted. |
| `LIM <pmin> <pmax> <rmin> <rmax>` | Soft limits (deg). Persisted. |
| `LIM OFF` | Disable soft limits. |
| `LIMHERE <PMIN\|PMAX\|RMIN\|RMAX>` | Set one limit to the current angle. |
| `INV <j2:0\|1> <j3:0\|1>` | Flip a motor's direction. Persisted. |
| `?` | Print a `cfg` line and a `st` line now. |

## Messages (Mega → host)
- Status, every 100 ms:
  `{"t":"st","j2":<steps>,"j3":<steps>,"p":<pitch deg, 1 decimal>,"r":<roll deg>,"c":<claw deg>,
    "mv":<0|1 anything moving>,"en":<0|1>,"tr":<0|1 trusted>,"spd":<%>,"wd":<0|1 watchdog tripped since last V>,
    "lim":"<5 chars for D22..D30: '-' not fitted, '0' ok, '1' pressed>","sw":<-1 none|0|1 claw switch>,"enc":<0|1>,"cu":<0|1 claw count is only an estimate>}`
  `cu` = 1 when there is no claw encoder and the claw has moved toward closed since it last reached the
  open stop (it may have slipped on an object, so the count can run ahead of the real claw). It goes back to 0
  when the claw is re-synced at the open stop (open overshoot, `HC`, claw switch) or `ZC`.

## Health (v3)
Every 500 ms, after a `st` line (never in the same loop pass as one):
`{"t":"hw","vcc":<5V rail volts, 2 dp>,"ram":<free bytes>,"ramt":8192,"cpu":<0-100 %>,"lps":<loop passes/s>,
  "lmax":<longest wait between stepper updates in the window, µs>,"txq":<bytes waiting in the TX queue>,"drop":<status lines dropped, total>,
  "ina":<0|1>,"v":<bus volts>,"ma":<mA>,"mw":<mW>}`  — `v`, `ma`, `mw` only when `ina` = 1.
- `vcc`: AVCC measured against the internal 1.1 V bandgap (ADC, non-blocking: switch the mux, start a conversion,
  read it on a later pass; vcc = 1.1 × 1023 / reading, using the averaged reading). Below ~4.6 V = the 5V rail is sagging.
- `ram`: gap between the heap end and the stack pointer.
- `cpu`: load as 100 − 100 × lps / (fastest lps seen since boot). The loop never idles, so an idle board reads
  near 0 % and extra work (JSON, EEPROM, stepping, I2C) shows as a slower loop. High `cpu` and high `lmax` mean steps get delayed.
- `lps`: loop passes in the window, scaled to per second. `lmax` resets every window. The steppers are also
  serviced every 16 characters while a JSON line is built, so long lines don't hold up steps.
- `ina`: an INA219 current sensor answered at I2C 0x40 at boot (SDA D20, SCL D21). Wire it in the 12V line
  (or the servo supply) to measure that rail. Read it every 500 ms with Wire timeout 3 ms; on a failed read
  leave the old values. Assume the common 0.1 Ω shunt (current LSB from the shunt-voltage register: 10 µV / 0.1 Ω = 0.1 mA).
- `drop`: count of lines `queueLine()` had to drop because the TX queue was full.

## Current sensors (v4)
- Up to four INA219 boards, probed once at boot at I2C 0x40, 0x41, 0x44, 0x45 (set by each board's A0/A1 jumpers).
  Same maths as v3 (0.1 Ω shunt: mA = shunt raw × 0.1, V = (bus raw >> 3) × 0.004). One register read per loop
  pass, round-robin, a full set refreshed every 500 ms; on a failed read keep the old values.
- `hw` keeps `ina` (now the number of sensors found, 0–4) and adds `"cs":[[addr,v,ma],...]` with one entry per sensor
  found (addr as a decimal number, e.g. 64 for 0x40; v 2 dp; ma 1 dp). The old `v`/`ma`/`mw` fields stay and
  mirror the first sensor, so older dashboards keep working.
- Per-motor current can't be measured directly: all drivers share one 12V copper pour. The dashboard's current test
  measures by difference with the arm still: drivers off → drivers on (holding) → only j2 moving (`M 25 0`, then back)
  → only j3 moving (`M 0 25`, then back) → claw moving. It needs at least one sensor on the 12V line.
- Estimate without sensors: A4988 coil current limit = Vref × 1.25 A (0.1 Ω sense resistors, from the design log).

## Servo current from its ground wire (v5, Arduino only)
- One jumper from the servo's ground wire (at the servo end) to **A0**. Arduino GND joins the servo supply ground at
  the supply end. The ground wire's own resistance `R` (mΩ) is the shunt: mA = mV_A0 / R × 1000.
- Off by default (a floating A0 reads noise). Saved in EEPROM: `shunt` (mΩ, 0 = off).
- ADC sharing with `vcc`: each 500 ms window first takes the 4 vcc samples (AVCC ref, bandgap channel, as now), then,
  if shunt > 0, switches to the internal 1.1 V reference on channel A0 (Mega: ADMUX = _BV(REFS1) | 0 with
  MUX5 cleared, i.e. INTERNAL1V1), waits 5 ms for the reference to settle (millis, non-blocking), discards the first
  conversion, then converts back-to-back (one ADSC start per loop pass, read when done) until the window ends,
  keeping the sum, count and peak. Before the next vcc phase switch back to AVCC + bandgap (already waits 2+ ms).
  mV = raw × 1100 / 1024.
- `hw` adds, when shunt > 0: `"sa":<mean mA, 0 dp>,"sap":<peak mA, 0 dp>` (negative clamps to 0).
- `cfg` adds `"shunt":<mΩ>`.
- Commands: `SHUNT <mΩ>` (0–1000, 0 = off, saved). `SCAL <mA>`: calibrate from a multimeter reading taken right now:
  shunt = (latest mean mV) / mA × 1000; refuse with err if the latest mean is under 2 mV or mA <= 0 ("Load the servo
  (grip something) and try again").
  Also refuse if the latest mean is over 300 mV ("A0 reads too high: check the jumper to the servo's black wire");
  the dashboard shows the same text instead of a value when sa × shunt / 1000 > 300.

## Claw is a servo (v2, replaces the 28BYJ-48 notes below)
- goBILDA 2000 Series Dual Mode servo (Torque), 300° range. Signal on **D11** (J27 IN4, pin 4; IN1–IN3 unused). Pulse 500–2500 µs = 0–300°.
  Power: the servo can draw over 2 A when it grips, which the Arduino's 5V can't supply. Feed its red wire from
  a separate 5–7.4 V supply and join that supply's ground to the Arduino ground.
- Claw angle `c` = degrees closed from the open point (0 = open). Servo angle = `open` + `c` × `dir`.
  Saved in EEPROM: `open` (servo degrees, default 150), `dir` (+1 or −1, default +1), close limit `cmax`
  (default 90). Clamp servo angle to 0..300 and `c` to 0..cmax.
- The servo knows its own position, so there is no drift: `cu` is always 0, `enc` 0, `sw` −1.
- Jog (`V` claw field) moves the commanded angle at up to 120°/s × |value|/100, updated smoothly (every ~10 ms),
  never stepping more than the rate allows. `GC <deg>` moves there at 120°/s. `S` / watchdog: claw holds where it is.
- `HC` = go to open (c = 0). `ZC` = the current servo angle becomes the open point (c = 0).
  `KC` = close limit = current c. New: `CDIR` flips dir (saved, and `open` stays put).
- On boot, write the saved claw angle before `attach()` so the servo doesn't jump to the middle first.
- `cfg` gains `"copen":<servo deg>,"cdir":<1|-1>`.

## Claw without sensors (v1.1, obsolete with the servo)
- The claw count can only be corrected at the open hard stop. So every move that ends at 0 (holding open, `GC 0`)
  keeps driving open a little past 0 (20°, at the slow home speed) into the stop, then sets the count to 0.
  The reported claw angle never goes below 0.
- Closing runs at a lower speed (more torque, fewer slipped steps); opening keeps the normal speed.
- A claw stall never changes the arm's `tr` flag.
- Config (on boot and after any config change):
  `{"t":"cfg","ver":1,"gear":1.0,"max":1200,"acc":1500,"lim":[pmin,pmax,rmin,rmax] or null,"inv":[0,0],"cmax":<claw close limit deg>}`
- Info / warnings: `{"t":"msg","s":"text"}`   Errors: `{"t":"err","s":"text"}`
- Boot: `{"t":"hello","fw":"ArmDashboard","ver":1}` then `cfg` then `st`.

Keep Serial output short: the status line must fit well inside the time budget (115200 baud ≈ 11 bytes/ms),
and the main loop must never block (no delay(), no blocking I2C beyond the existing timeout), so steps never stutter.
